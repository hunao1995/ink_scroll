# 墨卷 · Ink Scroll — 首次体验与破圈潜力评审

评审人视角：创意工具 / 消费级增长 PM。实测环境：本机 `http://127.0.0.1:8930/index.html`，Playwright chromium-1217，桌面 1440×900 与手机 390×844（isMobile+hasTouch）。截图见 `reviews/shots/growth-*.png`，原始数据 `reviews/shots/growth-probe.json`。线上站只核了 HTTP 200（282 KB，0.38 s），完整线上计时因字体加载超时**未核实**。

## 0 · 事实核验（任务书「已知事实」逐条）

| 说法 | 实测 | 结论 |

| README 0 张截图 | 中英 README 各 6 个 `![` 全是 shields 徽章，无一张产品图 | 属实 |

新发现的两个首屏缺陷：
- **22/42 张卡永远不可见**：`.mode-card:nth-child(1..6)` 才有 fade-up 动画，每组第 7 张起 opacity 停在 0（桌面、手机、11 s 后仍如此）。「声音 · 吟诵」「倾斜 · 掌中」「手机 · 众光」这些最有传播力的模态恰好在隐藏名单里。
- 副标题「一幅被墨盖住的画 · 光落在哪里，哪里才显色」渲染了两遍（`index.html:907` 与 `:909` 都绑 `tagline`）；桌面上吸底的「展开画卷」按钮压在「只用摄像头」分组标题上；手机上按钮文字折成两行。

## 1 · 新用户 10 秒旅程

| 秒 | 他看到 | 他想 | 流失点 |
|---|---|---|---|
| 0–1 | 羊皮纸底、loading 条；本机 0.9–1.6 s 出首屏（一次冷启动观测到约 6 s） | 「加载中」 | 移动网络下 4 MB 资源，大概率在这里关掉 |
| 1–3 | 大字「墨卷」+ 印章，同一句副标题两遍，然后一排排灰白卡片渐次浮现 | 「这是个……设置页？画在哪？」 | **没有任何一像素是作品本身**，是致命缺口 |
| 3–6 | 桌面：6 张卡 + 一张孤零零的「环境光·此浏览器可能不支持」漂在空白里；手机：3.5 屏卡片需要滚动 | 「要我先选一个？选错了会怎样？」 | 选择瘫痪；红字「不支持」是负面第一印象 |
| 6–8 | 找到底部「展开画卷」，点击，300 ms 淡出 | 「终于」 | 已损失一半人 |
| 8–10 | 整屏素描线稿，光标处一个直径约 280 px 的圆，里面是**几乎同样灰的水墨**；0.9 s 后浮出「移动鼠标或手指 · 揭示画卷」，三步引导在任何移动后即消失（桌面上鼠标本来就在动，引导实际一次都没被看到） | 「哦，有点意思……然后呢？」 | 揭示的「颜色」饱和度实测只有 0.13（山水图本身近乎单色），aha 偏弱 |

**首屏应该长什么样**：打开即是画。`#start-screen` 背景直接铺山水线稿，鼠标 / 手指一进页面就有光圈在揭示（也就是 `?preset=gallery` 的自动展卷放到首页来跑），标题与一行副标题浮在画上，一个按钮「换一种光」才展开 42 张卡。首屏只加载 1 张场景图 + 系统字体，其余 4 张与 Google Fonts 在开卷后懒加载。「展开画卷」改成不存在：首屏就是展开的。

## 2 · 传播钩子评估（11 种形式，可传播性 1–5）

| 形式 | 分 | 能变成什么 | 实测 / 判断 |
|---|---|---|---|
| 照亮（默认） | 3 | 一条 8 秒短视频 | 视觉成立，但录屏里灰揭灰不够抓眼；换成花鸟 / 星空做封面更好 |
| 累积 | 2 | — | 需要玩 5 分钟才有感知，无分享物 |
| 延迟 8 s | 3 | 短视频梗 | 「我的光慢半拍」有解释成本，但一旦看懂很想转 |
| 静默 | 1 | — | 需要麦克风 + 20 s 安静，录不出来 |
| **日课 `?daily=1`** | 4 | Wordle 式仪式 | 已实测：开卷后 URL 变 `?daily=1&mode=mouse&scene=0&style=paper&form=daily`，分享卡题款追加日期 `2026.10.29`。但现在种子只决定题款 / 印章位置 / 一处色相，**没有「今日这张画」的差异、没有连胜、没有可粘贴的文本结果**。Wordle 的转折点就是那串 emoji 格子（见 [Wikipedia: Wordle](https://en.wikipedia.org/wiki/Wordle)，2021-10 引入分享格式后才爆发）。墨卷的等价物应是：每日一幅固定场景 + 固定光圈数量上限 + 一行可复制的「墨卷 #N ▓▓░░░ 揭开 37%」 |
| **共处 `?form=together`** | 4 | 情侣 / 婚礼链接 | 已实测：单指针时光圈几乎不显色（中心饱和度 0.07），确实「一个人揭不开」。但两盏灯要么同一块触屏上两根手指，要么走 `server.py` 中继——GitHub Pages 上**异地两部手机做不到**。情侣链接要成立必须先有托管中继（哪怕是一个免费的 WebRTC 信令） |
| 供奉 | 2 | 一条慢视频 | 90 s 才熄灭，节奏对短视频太慢 |
| 驱赶 | 3 | 满足感视频 | 「推墨」类似 scratch-to-reveal（UI 库里已是标准组件，见 [inspira-ui scratch-to-reveal](https://github.com/unovue/inspira-ui/blob/eec920b047589058b4b02ba64deb614869e7237a/content/en/2.components/special-effects/scratch-to-reveal.md)），说明这个动作大众已懂，但也说明它本身不稀缺 |
| 召唤 | 3 | 短视频 | 粒子吸聚再炸开是最适合 15 秒竖屏的一种 |
| 书写 | 2 | — | 需要压感或快笔速，手机上感知弱 |
| 仪式 | 2 | 解谜梗 | 三点 5 秒内点完才开 10 秒，适合彩蛋不适合入口 |
| **上传自己的画** | 5（潜力） | 每个人自己的作品 | **当前不存在**：全文无 `<input type=file>`、无 FileReader、无拖放，只有 `?video=<url>`。这是最大的空白：把「揭示」套在用户自己的照片 / 孩子的画 / 婚纱照上，分享动机从「看我玩了一个作品」变成「看我的画」 |

## 3 · 渠道与节奏

**中文**
- 即刻：发一条 12 秒录屏（星空场景、召唤形式、手机竖屏），文案「一张被墨盖住的画，光落哪儿哪儿亮。纯网页，零安装」+ 链接。周二至周四晚 21–23 点。
- B 站：动态区而非投稿，一条 30 秒「手势 / 呼吸 / 摇手机三种揭法」对比视频，置顶评论放链接和 `?form=together` 的双人玩法。周末下午。
- 小红书：图文 9 宫格 = 9 张分享卡（现在卡的 95% 面积是线稿，需先把光圈放大到 40% 画面再截），标题走「一个人揭不开的画，发给对象试试」。先修 `og:image`，否则站外预览是空白。

**英文**
- Show HN：周二或周三美东早 8–10 点。对照 HN Algolia 检索（已打开），浏览器互动类 Show HN 常态在 70–100 分（如 WASM/WebGL Fluid Simulation 86 分、ncurses fluid sim 97 分）；标题要讲「单文件 + 42 种输入」这种工程事实而非「水墨艺术」，后者在 Show HN 里查不到任何先例。
- r/creativecoding：发 GIF（不发链接），标题写技法「Sobel ink layer + spotlight reveal, 0 deps, one HTML file」。**未核实**：Reddit 返回 403，未能看到该版近期热帖。
- TouchDesigner 社区：发 `examples/touchdesigner_osc.md` 的 OSC 接入短帖，这是唯一有现成「专业用户」钩子的渠道。

## 4 · 可量化目标

- **30 天**：看「点开 → 开卷」转化（现在首屏无画面，猜测 <50%，**未核实**，需埋一个无 cookie 的计数）；分享卡下载次数；GitHub stars 从 1 到 100 作为 Show HN 是否成立的最低门槛。
- **90 天**：`?daily=1` 的 7 日回访率（Wordle 式产品唯一重要的数字）；`?form=together` 链接被第二台设备打开的比例；带 `?video=` 或未来「上传」参数的 URL 占比（衡量「用自己的内容」是否发生）。

## 5 · 框架通用性的产品含义

从「水墨作品」改为「把任何图 / 视频变成可揭示装置的工具」：
- **首页**：要变成「拖一张图进来」，水墨五景降级为模板；今天连一个文件输入都没有，这一步最便宜也最关键。
- **定价**：核心单文件保持 MIT 开源；可收费的是托管中继（共处 / 众光 / 异地情侣链接都依赖它）、自定义域名的日课页、展厅 kiosk 的 DMX / OSC 支持包。不要卖「风格」，风格是传播素材。
- **名字**：保留「墨卷 · Ink Scroll」作为首个作品名，工具另起一个不带「墨」的名字；否则上传婚纱照的用户会觉得走错门。
- 利：市场从「喜欢水墨的人」扩到「有一张想被慢慢揭开的图的人」，分享动机天然成立。弊：失去「学者书房」的气质和 FORMS.md 里刻意不做裂变的伦理立场；42 种输入对工具用户是噪音而非卖点，首页要藏起 38 种。

## 6 · 最该先做的三条

1. **首屏即画面**：首页跑自动展卷，1 张图 + 系统字体先出，其余懒加载；顺手修 22 张永远不显示的卡、重复副标题、`og:image` 绝对路径、英文 README 的 21→42。
2. **分享闭环**：控制栏加「分享」按钮（现在只有键盘 `S`，手机根本存不了卡），卡上印 URL 或二维码，分享时把光圈放大到画面的 1/3 以上；日课加一行可复制文本结果。
3. **上传自己的画**：一个 `<input type=file accept=image/*>` + 拖放，复用 `?video=` 已有的「从当前帧生成墨层」管线。

## 摘要

- 首屏体验：**3/10**。有审美，但 0 像素作品、4 MB 资源、一半模态卡不可见、aha 时揭出的颜色太灰。
- 传播潜力：**6/10**。日课与共处两个形式的骨架已在，缺的是分享物（文本结果 / 二维码 / 托管中继）与「用自己的图」。
- 第一条该发的内容：即刻 / 小红书一条 12 秒竖屏录屏，星空场景 + 召唤形式，文案「一个人揭不开的画，发给对象试试」，附 `?form=together` 链接（前提：先修 og:image 与分享按钮）。
- 定位建议一句话：先把「墨卷」做成第一个样板作品，再把引擎独立成「任何图都能被光慢慢揭开」的工具，名字分开、托管收费、单文件开源。
- 未核实项：线上站完整加载计时；r/creativecoding 近期热帖；点开→开卷的真实转化率；日课种子除题款外的视觉差异。
